Агент-инструмент md2html

Контракт · параметры · обязательный вопрос · self-contained HTML
Вы собираете не reviewer для чужого diff, а агента-инструмент: он читает один resume.md и верстает один self-contained resume.html. Главный навык — engineering contract с узким write, параметрами и обязательным решением, которое агент добывает вопросом.

Что получится

  • .claude/agents/md2html.md — project-scope агент в Git;
  • resume.html, который открывается в браузере без внешних CSS, JS и шрифтов;
  • README.md с таблицей параметров и логом вопроса про контакты;
  • четыре демо-прогона log/run-a.md, log/run-b.md, log/run-c.md, log/run-d.md;
  • подтверждение, что исходный resume.md не изменился.

Вход

Возьмите вымышленный resume.md с разделами:

# Jane Doe
## Опыт
## Образование
## Навыки
## Проекты

Используйте только фейковые данные. Не вставляйте реальные телефоны, адреса, email, ссылки на приватные профили, токены и секреты. Для демо достаточно заглушек вида jane@example.com и @jane_fake.

Агент читает только один .md и пишет только один .html. Исходник он не редактирует.

Контракт агента

Создайте .claude/agents/md2html.md в вымышленном Workflow Kit. Минимальный frontmatter:

---
name: md2html
description: Read resume.md and render a self-contained resume.html. Read-only for the source; write only resume.html. Ask about contacts before rendering.
tools: Read, Write
model: inherit
---

Тело инструкции должно описывать:

  1. Роль: конвертер одного resume.md в один resume.html.
  2. Когда использовать: есть входной markdown-файл резюме и нужен локальный self-contained HTML.
  3. Действия: прочитать один .md, собрать HTML с inline CSS, записать только resume.html.
  4. Формат результата: готовый HTML, короткий отчёт о теме, выбранных секциях, контактах и предупреждениях.
  5. Условия остановки: нет файла — спросить; неизвестная тема — откат на light с предупреждением; после записи одного .html — стоп; исходник не трогать.

Явно запретите:

  • менять resume.md;
  • создавать копии resume-1.html, resume-final.html и подобные;
  • подключать внешние CSS, JS, шрифты и картинки;
  • придумывать контакты, если пользователь их не передал.

Параметры

В теле агента должна быть таблица параметров — это его сигнатура.

ВидПараметрПоведение
опциональныйtheme = light | dark, дефолт lightне указали — молча берёт light
опциональныйsections, дефолт — все блокине указали — верстает все; указали — только перечисленные
обязательное решениеконтакты в футередефолта нет: не передали — агент сначала спрашивает, а не решает за вас

Пресеты light и dark — короткие CSS-блоки прямо в инструкции агента. Не нужно тянуть внешнюю тему.

Правила поведения:

  • theme=dark — тёмная тема; theme=light или отсутствие — светлая;
  • theme=neon или другое неизвестное значение — откат на light и явная строка-предупреждение в отчёте;
  • sections=experience,skills — только эти разделы; неизвестный раздел — предупредить и пропустить;
  • контакты переданы сразу — используй их и не переспрашивай;
  • контактов нет — СНАЧАЛА спроси, что добавить в футер: телефон, email, ссылки. ТОЛЬКО ПОТОМ верстай;
  • пользователь ответил «нет, не надо» — пропусти футер целиком, не оставляй пустой блок и не пиши «контакты не указаны»;
  • нет входного файла — спроси, какой файл верстать, не выдумывай данные;
  • повторный прогон перезаписывает resume.html, а не плодит копии.
Главная ловушка — агент молча верстает, не спросив. Лечится дословной строкой в инструкции: «контакты не переданы — СНАЧАЛА спроси, ТОЛЬКО ПОТОМ верстай».

Четыре демо-прогона

Запускайте агента через @agent-md2html или через явное делегирование, если ваша версия Claude Code это поддерживает. Каждый прогон записывайте в отдельный файл в log/: запрос, вопрос агента, ваш ответ, итоговые параметры, результат и предупреждения.

Прогон A — без параметров

@agent-md2html свёрстай resume.md

Ожидаемое поведение: агент до вёрстки спрашивает про контакты. Вы отвечаете: «только email, jane@example.com». После этого он верстает resume.html в теме light, со всеми секциями и email в футере.

В логе должно быть видно: вопрос был задан до записи HTML, ответ пользователя и итоговый результат.

Прогон B — тёмная тема и фильтр секций

@agent-md2html свёрстай resume.md, theme=dark, sections=experience,skills,
contacts: email jane@example.com

Ожидаемое поведение: тёмная тема, только разделы «Опыт» и «Навыки», email в футере. Агент не переспрашивает про контакты, потому что они переданы сразу.

Прогон C — контакты переданы явно

@agent-md2html свёрстай resume.md, theme=light, contacts: telegram @jane_fake

Ожидаемое поведение: светлая тема, все секции, контакт в футере, вопроса про контакты нет. В отчёте видно, что контакт взят из запроса.

Прогон D — негативный сценарий

Сначала попросите агента сверстать несуществующий файл:

@agent-md2html свёрстай missing.md

Ожидаемое поведение: агент спрашивает, какой файл верстать, и не выдумывает содержимое.

Затем запустите:

@agent-md2html свёрстай resume.md, theme=neon, contacts: no

Ожидаемое поведение: тема откатывается на light, в отчёте есть явное предупреждение про neon, футер отсутствует целиком. Исходник не изменён, лишних файлов нет.

README

В README.md практики должны быть:

  • таблица параметров theme, sections, contacts;
  • описание дефолтов и отличия «опциональный» от «обязательное решение»;
  • лог вопроса про контакты: точная формулировка и ответ пользователя;
  • команды или запросы для четырёх прогонов;
  • ограничения: только resume.md на входе, только resume.html на выходе, без внешних ресурсов.

Проверка

  • .claude/agents/md2html.md лежит в project-scope и виден в Git.
  • tools — только Read и Write; нет Edit и Bash; model выбран осознанно.
  • В инструкции есть роль, триггер, действия, формат результата и stop conditions.
  • theme по умолчанию light; dark работает.
  • sections без значения верстает все блоки, с значением — только перечисленные.
  • Без контактов агент спрашивает до вёрстки; в логе это видно.
  • Ответ «нет» приводит к отсутствию футера, а не к пустому блоку.
  • Контакты, переданные в запросе, не вызывают повторного вопроса.
  • Неизвестная тема откатывается на light с предупреждением.
  • Отсутствующий файл приводит к вопросу, а не к выдуманному резюме.
  • Повторный прогон перезаписывает resume.html, а не создаёт копии.
  • resume.html открывается без внешних CSS, JS, шрифтов и картинок.
  • git diff -- resume.md пуст: исходник не изменён.
  • В log/ четыре прогона A–D; README содержит таблицу параметров и лог вопроса.
  • Нет реальных персональных данных, секретов и приватных ссылок.

Безопасность

  • Только вымышленное резюме и фейковые контакты.
  • Не используйте реальные имена, телефоны, адреса и email.
  • Не подключайте внешние ресурсы: self-contained HTML не должен делать сетевых запросов.
  • Не давайте агенту Bash, Edit или доступ к другим файлам: его задача — один вход и один выход.
  • Не публикуйте результат в открытый доступ без отдельного решения.

Если Claude Code недоступен

Создайте .claude/agents/md2html.md вручную и проверьте контракт по этому же чек-листу. Четыре прогона можно симулировать в редакторе: записать запрос, вопрос агента и ожидаемое поведение в log/, а resume.html собрать вручную по тем же правилам. Критерии проверки не меняются: контакты добываются вопросом, тема и секции работают, негативные ветки отработаны, исходник не изменён.
