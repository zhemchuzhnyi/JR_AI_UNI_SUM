Практика вебинара 8

Агент file2md

PDF · HTML · Excel · Python-скрипты · output contract
Главная идея — агент думает, скрипт пашет. LLM понимает человеческий запрос и переводит его в точный вызов, а узкий Python-скрипт делает тяжёлую работу с файлами. Скрипты вы не пишете руками: просите Claude Code создать их, зафиксировать зависимости и проверить запуск.

Что получится

  • .claude/agents/file2md.md — project-scope агент в Git;
  • три скрипта в .claude/scripts/: pdf2md.py, html2md.py, excel2md.py;
  • requirements.txt с точными версиями зависимостей;
  • README.md с двумя интерфейсами, output contract и таблицей выжимки;
  • четыре демо-прогона в log/: A, B, C, D;
  • фейковые входные файлы в input/ и результаты в output/.

Вход и выход

Используйте только вымышленные файлы:

input/
  report.pdf
  page.html
  data.xlsx
output/

Требования к данным:

  • PDF — небольшой вымышленный отчёт на 10–20 страниц;
  • HTML — простая страница с заголовками, списком и таблицей;
  • Excel — 2–3 листа с вымышленными строками;
  • никаких реальных персональных данных, договоров, счетов, токенов и секретов.

Агент читает файл из input/ и пишет .md в output/ или рядом с исходником, если output не указан. Другие каталоги он не трогает.

Два интерфейса

У практики два разных интерфейса, и их нельзя смешивать.

Интерфейс для человека

Человек говорит агенту живым языком:

достань первую, среднюю и последнюю страницы report.pdf

Интерфейс для скрипта

Скрипт понимает только точный машинный вызов:

python .claude/scripts/pdf2md.py input/report.pdf output/report.md --pages 1,10,20

У всех трёх скриптов общий интерфейс:

<script> <input> <output> [--pages n,n]
<script> <input> --info

--info — служебный вызов: он возвращает метаданные, например количество страниц PDF, список листов Excel или размер HTML. --pages принимает только конкретные номера. Понимание слов «первая, средняя, последняя» — работа агента, а не скрипта.

Скрипт остаётся тупым, узким и надёжным. Вся гибкость понимания языка — в агенте.

Параметры агента

В теле file2md.md должна быть таблица параметров:

ВидПараметрПоведение
обязательныйпуть к входному файлунет файла — стоп
опциональныйtype = auto | pdf | html | excelauto определяет по расширению; можно перебить явно
опциональныйpages словами: «первую, среднюю, последнюю»агент переводит слова в числа; для HTML — честный отказ, у него нет страниц
опциональныйoutputкуда класть .md; дефолт — рядом с исходником

Правила:

  • type=auto — определить формат по расширению; неизвестное расширение — честный отказ, а не догадка;
  • pages для PDF — сначала вызвать --info, получить количество страниц, вычислить номера, затем вызвать скрипт с --pages;
  • pages для HTML — сказать, что у HTML нет страниц, и предложить извлечь весь документ;
  • pages для Excel — если страницы не поддерживаются, честно отказать или предложить листы;
  • output не указан — писать рядом с исходником;
  • повторный прогон перезаписывает результат, а не плодит копии.

Контракт агента

Минимальный frontmatter:

---
name: file2md
description: Extracts Markdown from PDF, HTML and Excel using Python scripts. Understands human page requests and calls the right script.
tools: Read, Glob, Grep, Bash, Edit, Write
model: inherit
---

Тело инструкции должно содержать:

  1. Роль: агент-переводчик между человеческим запросом и узкими Python-скриптами.
  2. Когда использовать: нужно извлечь markdown из PDF, HTML или Excel.
  3. Действия: определить тип, при необходимости вызвать --info, перевести параметры, вызвать нужный скрипт, проверить exit code.
  4. Границы: скрипты только в .claude/scripts/; не трогать ничего за пределами input/, output/ и .claude/scripts/; выход за границу — стоп.
  5. Формат результата: команда, exit code, что извлечено, что не удалось, путь к файлу.
  6. Stop conditions: нет входного файла — спросить; неизвестный формат — отказ; скрипт упал — показать лог, не писать «готово»; HTML с --pages — честный отказ.

Bash здесь опаснее, чем в read-only reviewer: он запускает Python. Поэтому границы каталогов и stop conditions обязательны. Edit/Write нужны только для создания скриптов и результатов, а не для правки чужих файлов.

Скрипты

Попросите Claude Code создать три узких скрипта:

ФорматБиблиотекиЧто делает
PDFpdfplumberизвлекает текст по страницам
HTMLbeautifulsoup4 + markdownifyпревращает HTML в markdown
Excelopenpyxlчитает листы и строки, собирает markdown-таблицы

Требования к скриптам:

  • общий CLI: <input> <output> [--pages n,n] и --info;
  • --info не пишет выходной файл, а печатает метаданные;
  • неизвестный формат или отсутствующий файл — понятная ошибка и ненулевой exit code;
  • никаких сетевых запросов и удаления файлов;
  • зависимости зафиксированы в requirements.txt точными версиями.

Пример вызова:

python .claude/scripts/pdf2md.py input/report.pdf --info
# -> 20 страниц

python .claude/scripts/pdf2md.py input/report.pdf output/report.md --pages 1,10,20
# -> exit code 0, output/report.md готов
Главная ловушка — агент гадает «среднюю» без --info. В инструкции должно быть явно: сначала --info, потом вычислить страницы, потом --pages.

Output contract

После каждого запуска агент обязан вернуть:

  • какой скрипт и с какими аргументами запущен;
  • exit code;
  • что извлечено: формат, страницы/листы, путь к .md;
  • что не удалось и какой лог это подтверждает;
  • changed files и границы: не выходил ли он за input/, output/, .claude/scripts/.

Если скрипт упал, агент не врёт «готово», а показывает stderr/stdout и завершает работу с ошибкой.

Четыре демо-прогона

Каждый прогон записывайте в отдельный файл в log/: запрос, команды, exit code, результат и вывод.

Прогон A — PDF и слова про страницы

достань первую, среднюю и последнюю страницы report.pdf

Ожидаемое поведение:

  1. pdf2md.py input/report.pdf --info → например, 20 страниц;
  2. агент вычисляет 1,10,20;
  3. pdf2md.py input/report.pdf output/report.md --pages 1,10,20 → exit code 0.

В логе должны быть видны оба вызова — служебный и рабочий.

Прогон B — HTML и честный отказ от страниц

достань первую страницу page.html

Ожидаемое поведение: агент объясняет, что у HTML нет страниц, и предлагает извлечь весь документ. Если пользователь соглашается — запускает html2md.py input/page.html output/page.md и возвращает exit code 0. Не выдумывает страницы и не подставляет --pages.

Прогон C — Excel и явный type

извлеки data.xlsx, type=excel, output=output/data.md

Ожидаемое поведение: агент запускает excel2md.py input/data.xlsx output/data.md, проверяет exit code и перечисляет листы/строки. type=auto тоже должен работать, если расширение .xlsx.

Прогон D — негативный сценарий

Сначала:

извлеки missing.pdf

Ожидаемое поведение: агент останавливается и спрашивает файл, не выдумывает содержимое.

Затем:

извлеки input/unknown.bin

Ожидаемое поведение: честный отказ, ненулевой exit code или объяснение, почему формат не поддержан. Никаких пустых .md «на всякий случай».

README

В README.md практики должны быть:

  • два интерфейса: человеческий и машинный;
  • таблица параметров type, pages, output;
  • output contract;
  • таблица выжимки: размер входа → размер .md, сколько страниц/листов извлечено;
  • команды запуска и ограничения;
  • список зависимостей и версий.

Не пишите «markdown эффективнее в 150 раз»: покажите реальный замер, например «PDF 1.8 МБ → 12 КБ текстовой сути; отброшены служебные и оформительские блоки». Это разные утверждения.

Проверка

  • .claude/agents/file2md.md лежит в project-scope и виден в Git.
  • Агент и три скрипта закоммичены; requirements.txt содержит точные версии.
  • type=auto работает для PDF, HTML и Excel; неизвестный формат даёт честный отказ.
  • pages словами доказан логом: сначала --info, потом --pages с числами.
  • Для HTML с --pages — честный отказ, без выдуманных страниц.
  • Нет входного файла — агент спрашивает, а не выдумывает данные.
  • Скрипт упал — агент показывает лог, а не пишет «готово».
  • В инструкции есть границы input/, output/, .claude/scripts/ и stop conditions.
  • Четыре демо-прогона A–D лежат в log/.
  • README.md содержит два интерфейса, output contract и таблицу выжимки.
  • Повторный прогон перезаписывает результат, а не плодит копии.
  • В материалах только вымышленные файлы, без реальных данных и секретов.

Безопасность

  • Не используйте реальные PDF, договоры, счета, резюме и персональные данные.
  • Не давайте агенту доступ к домашней папке и чужим репозиториям.
  • Скрипты работают только с input/, output/ и .claude/scripts/.
  • Запрещены сетевые запросы, установка пакетов из случайных источников и удаление файлов.
  • requirements.txt фиксирует версии; устанавливайте зависимости в отдельное виртуальное окружение.
  • Не публикуйте результаты с чувствительными данными.

Если Claude Code недоступен

Создайте file2md.md, три скрипта и requirements.txt вручную либо используйте готовые локальные скрипты с тем же CLI. Четыре демо-прогона можно выполнить на фейковых файлах вручную; если Python-библиотек нет, симулируйте --info, --pages и exit codes в log/ и честно отметьте, что именно не запускалось. Критерии проверки не меняются: границы, честные ошибки, оба вызова для pages и отсутствие реальных данных.
