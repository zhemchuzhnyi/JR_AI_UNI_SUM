team-kit и проверка plugin

Упаковка skills · локальная проверка · решение по чужому plugin
Два задания: собрать собственный team-kit из git-commit и prompt-improve, затем проверить чужой plugin до установки и записать инженерное решение.

Что получится

  • team-kit — минимальный plugin с двумя skills из вебинара 5;
  • plugin.json и README.md пакета;
  • локальная проверка через --plugin-dir, /reload-plugins и validate;
  • PLUGIN_REVIEW.md и PLUGIN_DECISION.md по чужому кандидату;
  • понимание, когда plugin оставить локально, а когда не ставить вообще.

Часть 1. Соберите team-kit

Берите готовые skills из вебинара 5, а не пишите новое поведение. Смысл упражнения — упаковка.

Этап 1. Контейнер

Создайте в вымышленном Workflow Kit:

team-kit/
  .claude-plugin/
    plugin.json
  skills/
    git-commit/
      SKILL.md
    prompt-improve/
      SKILL.md
  README.md

plugin.json:

{
  "name": "team-kit",
  "version": "0.1.0",
  "description": "Team git-commit and prompt-improve skills",
  "author": { "name": "Platform team" }
}

Проверьте главное: manifest лежит в .claude-plugin/, а skills/ — в корне плагина. Если положить skills/ внутрь .claude-plugin/, plugin может загрузиться, но skills молча пропадут.

Этап 2. Локальная проверка

Загрузите пакет из папки, не публикуя:

claude --plugin-dir ./team-kit

Внутри сессии проверьте полный namespace:

/team-kit:git-commit
/team-kit:prompt-improve

Затем перезагрузите после правки и проверьте manifest:

/reload-plugins
claude plugin validate ./team-kit

Команды и флаги могут отличаться в вашей версии; важна логика: загрузили из папки, вызвали под namespace, перезагрузили после правки, проверили manifest.

Этап 3. README и границы

В README объясните:

  • что внутри;
  • как поставить локально;
  • как вызывать оба skill;
  • что git-commit запускается вручную;
  • какие права и ограничения у пакета.

Не добавляйте реальные ключи, токены и боевые команды.

Этап 4. Бонус: marketplace

Если хотите пройти путь до командной раздачи, заведите вымышленный team-tools с .claude-plugin/marketplace.json, добавьте каталог и установите team-kit@team-tools. Это бонус, а не обязательный минимум.

Часть 2. Проверьте чужой plugin

Возьмите публичный кандидат из практики вебинара — andrej-karpathy-skills — или другой plugin, который вам советовали.

Этап 1. Поймите, что это

Ничего не устанавливая, прочитайте README, CLAUDE.md и SKILL.md в репозитории. Своими словами запишите, что plugin делает и какую workflow-боль закрывает.

Этап 2. Оцените до установки

Заполните PLUGIN_REVIEW.md:

  • автор и источник: кому доверяем и почему;
  • состав: skills, agents, hooks, MCP, shell, сеть, credentials;
  • context cost и model-invoked поведение;
  • пересечения с вашими skills;
  • подходит ли среда и workflow;
  • путь обновления и удаления.

Этап 3. Проверьте на своей задаче

Если кандидат выглядит безопасно, поставьте его в user или local scope. Возьмите одну намеренно расплывчатую задачу из учебного проекта и сравните результат до и после установки. Не используйте реальные ключи, PR и секреты.

Если plugin содержит hooks, shell, сеть или credentials без внятного объяснения — не устанавливайте его. Это нормальный результат практики.

Этап 4. Примите решение

Запишите в PLUGIN_DECISION.md: оставляем, отключаем или удаляем. Укажите причину, scope, ограничения и команду отката.

Проверка

  • team-kit имеет manifest в .claude-plugin/ и skills в корне.
  • Оба skill вызываются под /team-kit:....
  • README объясняет установку, вызов и границы.
  • validate проходит или ручная проверка структуры подтверждает корректность.
  • Для чужого plugin заполнены автор, capability surface и поддерживаемость.
  • Решение по чужому plugin записано с причиной и путём отката.
  • Нет реальных ключей, секретов и опасных установок.
  • Вы можете объяснить, почему часть кандидатов оставили без установки.

Безопасность

  • Используйте только учебный Workflow Kit и фейковые данные.
  • Не публикуйте плагин в открытый marketplace без отдельного решения.
  • Не устанавливайте незнакомый plugin с hooks, shell, сетью или credentials «просто посмотреть».
  • Для реального ключа используйте только локальный .env с ограниченным бюджетом; в заметках не сохраняйте значение.
