Permission modes и approval model

Claude Code

2 уровень · 3 лекция
Permission mode задаёт, какие действия Claude Code может выполнять и когда нужно подтверждение. Prompt описывает задачу, режим разрешений — границы действий.

Три разных слоя

Git baseline

«Как откатываться, если стало плохо?» Понятное исходное состояние и возможность восстановиться: отдельная ветка, Git status и diff.

Permission mode

«Что Claude может делать в этой сессии?» Какие действия разрешены и для чего потребуется approval.

Prompt / task

«Что вообще нужно сделать?» Цель работы и ожидаемый результат.

Вместе — безопаснее

Ветка и аккуратный prompt не заменяют подходящий режим разрешений.

Формула безопасной работы: Git baseline + безопасные разрешения + полезные проектные инструкции + гигиена памяти + diff, тесты и человеческое ревью. Порядок: сначала репозиторий и scope, затем режим доступа, только потом — задача.

Чем менее понятна задача, чувствительнее область и выше цена ошибки, тем строже выбирайте режим.

Что можно, а что спрашивается

Обычно свободно

Чтение файлов, поиск по коду, просмотр логов.

Через явное подтверждение

Запись в файлы, команды с побочными эффектами, массовые правки.

Разрушительные команды, чувствительные пути и обход ограничений не должны становиться рутиной. Approval — сигнал, что цена ошибки выросла, и он работает в связке со scope: ограничили задачу одним модулем — изменения за его пределами сразу подозрительны.

«Не задавай лишних вопросов» — самообман: при широкой формулировке даже небольшая правка может задеть README, тесты и конфиг. Вместо этого задайте рамку: сначала план, затем изменения только в допустимых пределах.

Режимы по степени свободы

  1. Исследование / только чтение: понять код, собрать факты и подготовить план без изменений.
  2. Обычная работа с подтверждениями: может готовить правки, но на чувствительных шагах ждёт человека; базовый выбор для разработки.
  3. Ускоренная локальная работа: оправдана только при трёх условиях сразу — низкий риск зоны, узкий scope, дешёвый и очевидный откат.
  4. Максимально свободный режим: только для узкого эксперимента в одноразовой песочнице.

Названия режимов (default, plan, acceptEdits и другие) могут меняться между версиями; ориентируйтесь на их поведение и сверяйтесь со справкой.

Актуальные названия из вебинара: Plan, Manual (default), Auto-Accept (acceptEdits), Auto Mode, YOLO (bypassPermissions / --dangerously-skip-permissions). Переключение — Shift+Tab в CLI/JetBrains или селектор в VS Code/Desktop; текущий режим виден в статус-баре. defaultMode в ~/.claude/settings.json задаёт стартовый режим. В новых версиях Claude Code Auto Mode может быть стартовым для интерактивных сессий на разных планах; в курсовом Gateway-режиме доступность зависит от модели и провайдера. Поэтому всегда проверяйте статус-бар и при необходимости переключите режим.

В некоторых версиях также доступен dontAsk: он не равен bypassPermissions, поэтому проверяйте фактическое поведение через /permissions. Режим bypassPermissions включается отдельно — его не получишь случайным нажатием. В статус-баре auto выглядит как ⏵⏵ auto mode on, Manual — как ⏸ manual mode on.

Сценарий: сначала расследование

  1. Проверьте репозиторий и определите scope.
  2. Начните с чтения и анализа без правок.
  3. Попросите перечислить факты, затронутые файлы, гипотезу и план проверки.
  4. После подтверждения причины выделите узкую правку в отдельную сессию с подходящим режимом.
  5. Посмотрите diff и результаты тестов; сами решите, принимать ли изменения.

Пример из лекции — исследование в отдельной ветке:

git switch -c investigate/refund-order
claude --permission-mode plan

После подтверждения причины — отдельная ветка и сессия для узкой правки:

git switch -c fix/refund-label
claude --permission-mode default

Одна задача — две сессии с разными режимами: не паранойя, а экономия внимания. Менять режим посреди сессии нормально, если причина инженерная; «просто устал от подтверждений» — предвестник странного diff.

Перед запуском проверьте актуальные режимы через claude --help или /help. Если не знаете, какой режим активен, выясните это, а не делайте вывод по поведению Claude.

Формулировки, которые поддерживают режим

Prompt задаёт рамку, а approval следит, чтобы за неё не вышли незаметно.

Запрос на расследование:

Исследуй, почему в inbox refund-запросы идут в неверном порядке.
Файлы пока не меняй.
Верни: затронутые файлы, гипотезу причины, план проверки.

Запрос на правку с явным scope:

Исправь только сортировку refund-запросов в модуле inbox.
Публичный API не меняй.
Если потребуется выйти за src/orders/refund/**, сначала остановись и объясни зачем.
После правки покажи diff и какие проверки нужно запустить.

Плохо: «Исправь всё быстро и не задавай вопросов». Лучше: «Сначала предложи план. Меняй только src/orders/refund/**. Публичный API не трогай. Если нужен другой файл — сначала объясни почему. После правки покажи diff».

Где нужен особый контроль

Осторожнее работайте с платежами, авторизацией, миграциями, конфигурацией и финансовыми расчётами. Запись файлов, команды с побочными эффектами и массовые изменения требуют повышенного внимания.

В чувствительной зоне ветка удешевляет откат, но не делает дешёвой смысловую ошибку: если Claude изменит контракт, расчёт комиссии или сценарий авторизации, вред определяется тем, насколько легко вы это заметите. Поэтому сначала — исследование и план, затем очень аккуратные правки под явным контролем.

  • Заранее укажите допустимые файлы и запретите изменения за пределами scope.
  • Не ослабляйте режим только ради сокращения количества подтверждений.
  • Не пытайтесь обходить ограничения организации через локальные настройки.
Сомневаетесь в режиме, scope или откате — начинайте со строгого режима и только чтения.

Что запомнить

  • Подтверждение — сигнал, что действие рискованнее обычного и выходит за привычные границы.
  • Prompt не может расширить разрешения, заданные permission mode.
  • Не ослабляйте режим только потому, что подтверждения мешают работать.
  • Смену режима посреди сессии оправдывает инженерная причина, а не усталость от подтверждений.
  • Если неизвестны затрагиваемые файлы, scope или способ отката, выбирайте более строгий режим.

Правило по умолчанию: сомневаетесь — выбирайте более строгий режим.

Практика (15–25 минут)

Цель: Сравнить Plan и Manual на одной и той же небольшой задаче.

Что сделать

  1. В учебном репозитории с notes.txt запустите claude --permission-mode plan и попросите исследовать файл и предложить правку. Убедитесь, что код не меняется.
  2. Выйдите из сессии и запустите claude --permission-mode default с той же узкой задачей.
  3. Пройдите approval на изменение, посмотрите diff и убедитесь, что правка только одна.
  4. Переключите режим через Shift+Tab, найдите текущий режим в статус-баре и запишите, почему для этой задачи выбран именно он.

Если Claude Code недоступен: выполните доступную часть шагов вручную в редакторе и терминале; недоступные команды разберите по официальной документации. Критерии проверки те же.

Проверка

  • В Plan не было изменений файлов.
  • В Manual было явное подтверждение перед правкой.
  • Вы можете объяснить выбор режима через риск, scope и цену отката.

Не используйте YOLO на реальном проекте; для практики достаточно Plan и Manual.

Approval — часть инженерного контроля: решение о принятии правки остаётся за человеком.
