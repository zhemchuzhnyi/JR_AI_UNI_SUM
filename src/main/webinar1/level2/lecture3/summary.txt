# Саммари лекции 3

## Permission modes и approval model — Claude Code, 2 уровень

Permission mode определяет, какие действия Claude Code может выполнять и когда ему требуется подтверждение. Выберите режим **до постановки задачи**: prompt задаёт цель, а режим — границы допустимых действий.

Безопасная работа сочетает Git baseline, подходящие разрешения, полезные проектные инструкции, гигиену памяти, проверку diff и тестов, а также человеческое ревью. Порядок действий: сначала репозиторий и scope, затем режим доступа и только потом — задача.

## Не путайте три слоя

- **Git baseline** — отвечает на вопрос «Как откатываться, если стало плохо?»: отдельная ветка, понятные изменения, diff.
- **Permission mode** — отвечает на вопрос «Что Claude может делать в этой сессии?»: исследовать, предлагать, править, спрашивать подтверждение.
- **Prompt / task** — отвечает на вопрос «Что вообще нужно сделать?»: цель работы и ожидаемый результат.

Один слой не заменяет другой: хорошая ветка или осторожная формулировка не компенсируют слишком свободный режим.

## Что можно, а что спрашивается

Часть действий Claude выполняет спокойно, часть проходит через ваш явный контроль:

- **Свободно** — чтение файлов, поиск по коду, просмотр логов.
- **Через approval** — запись в файлы, команды с побочными эффектами, массовые правки.

Разрушительные команды, чувствительные пути и обход ограничений не должны становиться рутиной. Approval — сигнал, что цена ошибки выросла, и он работает в связке со scope: ограничили задачу одним модулем — изменение за его пределами сразу подозрительно.

«Не спрашивай лишнего» — самообман: при широкой формулировке даже небольшой фикс может задеть README, тесты и конфиг. Правильнее задать рамку: сначала план, затем правка только в допустимых пределах.

## Как выбирать режим

Ориентируйтесь на степень свободы, а не только на название режима — оно может измениться между версиями (default, plan, acceptEdits и другие):

1. **Исследование, только чтение** — разобраться в коде, собрать факты и предложить план без правок.
2. **Обычная работа с подтверждениями** — может готовить правки, но на чувствительных шагах ждёт человека; базовый выбор для разработки.
3. **Ускоренная работа с меньшим числом подтверждений** — допустима, только если совпадают три условия сразу: зона низкорисковая, scope узкий, откат дешёвый и очевидный.
4. **Максимально свободный режим** — только для узкого эксперимента в одноразовой песочнице.

Актуальные названия из вебинара: **Plan** (исследование), **Manual** (`default`, спрашивает перед изменениями), **Auto-Accept** (`acceptEdits`, авто-одобрение правок файлов), **Auto Mode** (классификатор проверяет команды), **YOLO** (`bypassPermissions` / `--dangerously-skip-permissions`, только изолированная среда). Переключение: `Shift+Tab` в CLI и JetBrains, селектор в VS Code/Desktop; текущий режим виден в статус-баре. `defaultMode` в `~/.claude/settings.json` задаёт стартовый режим; на Pro/Max/Team новые сессии могут стартовать в auto — проверяйте статус-бар. Режим `bypassPermissions` включается отдельно — его не получишь случайным нажатием. В статус-баре auto выглядит как `⏵⏵ auto mode on`, Manual — как `⏸ manual mode on`.

Чем менее понятна задача, чувствительнее область и выше цена ошибки, тем строже должен быть режим. Запись, команды с побочными эффектами и массовые изменения требуют большего контроля; особенно осторожно относитесь к платежам, авторизации, миграциям, конфигурации и финансовым расчётам. В этих зонах ветка удешевляет откат, но не делает дешёвой смысловую ошибку: если Claude изменит контракт, расчёт комиссии или сценарий авторизации, вред определяется тем, насколько легко вы это заметите.

## Практический порядок работы

1. Проверьте репозиторий и определите точный scope задачи.
2. Для расследования начните с режима только для чтения и попросите Claude перечислить факты, затронутые файлы, гипотезу и план проверки — без изменений.
3. Если причина подтверждена, выполните узкую правку в отдельной сессии с подходящим режимом и approvals.
4. Явно ограничьте файлы и изменения, например запретите менять публичный API.
5. Проверьте diff и тесты; решение о принятии изменений остаётся за человеком.

Пример запуска на исследование — отдельная ветка и плановый режим:

```bash
git switch -c investigate/refund-order
claude --permission-mode plan
```

```text
Исследуй, почему в inbox refund-запросы идут в неверном порядке.
Файлы пока не меняй.
Верни: затронутые файлы, гипотезу причины, план проверки.
```

Когда причина подтверждена, правку выносят в отдельную сессию с обычным режимом и явными approvals:

```bash
git switch -c fix/refund-label
claude --permission-mode default
```

```text
Исправь только сортировку refund-запросов в модуле inbox.
Публичный API не меняй.
Если потребуется выйти за src/orders/refund/**, сначала остановись и объясни зачем.
После правки покажи diff и какие проверки нужно запустить.
```

Одна задача — две сессии с разными режимами: это экономия внимания, а не паранойя. Менять режим посреди сессии нормально, если причина инженерная; «просто устал от подтверждений» — повод насторожиться.

Доступные режимы, команды и способы переключения зависят от версии. Проверяйте их через `claude --help` или `/help`; если не уверены в текущем режиме, сначала выясните его, а не судите по поведению Claude.

## Что запомнить

- Подтверждение — сигнал, что действие рискованнее обычного и выходит за привычные границы.
- Prompt не может расширить разрешения, заданные permission mode.
- Не ослабляйте режим только потому, что подтверждения мешают работать.
- Смену режима посреди сессии оправдывает инженерная причина, а не усталость от подтверждений.
- Если неизвестны затрагиваемые файлы, scope или способ отката, выбирайте более строгий режим.

**Правило по умолчанию: сомневаетесь — выбирайте более строгий режим.**

## Практика (15–25 минут)

**Цель:** Сравнить Plan и Manual на одной и той же небольшой задаче.

**Что сделать:**
1. В учебном репозитории с `notes.txt` запустите `claude --permission-mode plan` и попросите исследовать файл и предложить правку. Убедитесь, что код не меняется.
2. Выйдите из сессии и запустите `claude --permission-mode default` с той же узкой задачей.
3. Пройдите approval на изменение, посмотрите diff и убедитесь, что правка только одна.
4. Переключите режим через `Shift+Tab`, найдите текущий режим в статус-баре и запишите, почему для этой задачи выбран именно он.

**Проверка:**
- В Plan не было изменений файлов.
- В Manual было явное подтверждение перед правкой.
- Вы можете объяснить выбор режима через риск, scope и цену отката.

> Не используйте YOLO на реальном проекте; для практики достаточно Plan и Manual.
