# Саммари лекции 1

## Claude Code — агент, а не просто чат

Обычный ИИ-чат отвечает на вопросы по тексту или фрагментам кода. Claude Code работает внутри проекта: изучает файлы и структуру, ищет связанную логику, предлагает план, меняет код и запускает команды.

Именно поэтому в курсе используется слово **agentic**: инструмент не только рассуждает, но и действует — выполняет ограниченные действия внутри рабочей среды (читает файлы, ищет по кодовой базе, правит код и запускает команды).

Claude Code — это **агент-оболочка**, а не сама модель: оболочка даёт терминал, доступ к файлам, цикл работы и правила безопасности, а «думает» подключённая LLM; её можно менять, в том числе через `settings.json` (в курсе — через Gateway JavaRush).

Это делает его полезнее, но повышает цену ошибки: изменения могут повлиять на реальный проект и его бизнес-правила.

## Главное правило

**Claude ускоряет инженерную работу, но за результат всё равно отвечаете вы.**

Нужно самому определить границы задачи, проверить изменения и решить, принимать ли их. Даже небольшая правка может изменить поведение системы: например, добавить к правилу «поднимать срочные возвраты» ещё и возвраты на сумму выше заданной.

## Рабочий цикл

1. Сформулировать конкретную задачу.
2. Дать Claude изучить нужный контекст.
3. Попросить план или ограниченное изменение.
4. Просмотреть **diff** — список фактических изменений: какие строки добавлены, удалены или изменены между старой и новой версией файлов. Именно diff показывает, что произошло на самом деле, а не что Claude обещал в тексте.
5. Запустить подходящие проверки: тесты, сборку, линтер или проверку ключевого сценария.
6. Оценить результат и принять решение.

Коротко цикл выглядит так: **задача → контекст → план → изменение → проверка → решение**.

В вебинаре этот же цикл называют **agentic loop**: prompt → сбор контекста → действие → проверка результата → решение человека (принято или доработка). В цикле вы не пассивный наблюдатель: можно добавить контекст, прервать действие (Esc) или направить Claude, если он уходит не туда. Если результата недостаточно, цикл возвращается к сбору контекста; если достаточно — Claude останавливается и ждёт следующий prompt.

Для сложной или рискованной задачи полезно сначала попросить план без изменений. Не стоит давать расплывчатые поручения вроде «сделай красиво»: они оставляют слишком много свободы для изменений за пределами задачи.

Пример здорового диалога: «Исправь порядок отображения возвратов. Сначала покажи план.» — в ответ Claude называет найденные файлы и предлагает, что проверить, а затем вы просите показать diff и план проверки.

## Действовать и отвечать — не одно и то же

Claude ускоряет поиск по проекту, черновой план и код, запуск типовых команд и подготовку сводки изменений. Но бизнес-ответственность он не несёт и контекст команды знает не так, как вы: решение, что вообще менять, границы задачи, чтение и оценка **diff**, интерпретация проверок и приёмка результата остаются за человеком.

Опаснее всего не полностью ошибочный ответ, а аккуратное изменение, которое слегка выходит за рамки задачи: заодно переименованы поля, подправлен соседний метод, «стало чище». В такой момент уместно сказать «стоп, это вне задачи» или «покажи только план».

## Пример курса

**Commerce OS** — воображаемый интернет-магазин, на котором разбираются примеры курса. Скачивать или настраивать его не нужно. Его модуль возвратов помогает показать, как ИИ может найти связанную сортировку, контроллер и тесты, а затем предложить конкретный план работы.

## Что запомнить

- Claude Code может не только советовать, но и действовать в рабочей среде.
- Аккуратный на вид diff всё равно может менять бизнес-логику.
- Следует проверять не только ответ Claude, но и фактические изменения и результаты проверок.
- Учить стоит принципы — задача, границы, diff, проверка, решение — а не только названия команд. Интерфейс и команды могут измениться, подход останется.
- Действовать и отвечать за последствия — не одно и то же: решение и бизнес-ответственность остаются за человеком.

## Подготовка к следующим лекциям

Перед установкой Claude Code подготовьте **Git** и **Node.js LTS**. Git нужен, чтобы видеть изменения и при необходимости их отменять. Node.js пригодится как запасной способ установки через npm и в дальнейшей работе с фронтенд-частью.

Ставьте Node.js с пометкой **LTS** — это стабильная ветка. Примеры установки (команды актуальны на момент написания; сверяйтесь с официальной документацией):

```bash
# macOS
brew install git
brew install node
# если Homebrew нет, Git можно поставить через Command Line Tools:
xcode-select --install
```

```bash
# Linux
sudo apt install git        # Debian / Ubuntu
sudo dnf install git        # Fedora / RHEL
nvm install --lts           # Node.js через nvm
```

```bash
# Windows
winget install --id Git.Git
winget install --id OpenJS.NodeJS.LTS
```

После установки откройте новое окно терминала и проверьте:

```bash
git --version
node --version
npm --version
```

Если команды показывают версии, среда готова. Если появляется `command not found`, сначала откройте новый терминал: возможно, PATH ещё не обновился.

## Практика (15–25 минут)

**Цель:** Почувствовать agentic loop и научиться принимать результат по diff, а не по описанию.

**Что сделать:**
1. Создайте учебную папку `claude-practice/agent-loop`, выполните `git init`, создайте `header.txt` с двумя строками: `Refund requset` и `Do not touch this line`, затем сделайте первый коммит.
2. Запустите Claude из папки и попросите: «Исправь только `Refund requset` на `Refund request`. Ничего больше не меняй. Сначала покажи план, потом diff».
3. Проверьте план, разрешите правку и посмотрите `git diff`. Убедитесь, что изменилась только одна строка.
4. В копии папки попросите «сделай файл аккуратнее» и сравните diff. Не принимайте изменения: отметьте, что было бы helpful overreach.

**Если Claude Code недоступен:** выполните доступную часть шагов вручную в редакторе и терминале; недоступные команды разберите по официальной документации. Критерии проверки те же.

**Проверка:**
- В первом diff изменилась только строка с опечаткой.
- Вы можете объяснить, где в цикле был сбор контекста, действие, проверка и решение человека.
- Вы назвали хотя бы один пример «заодно», который не входил в задачу.
