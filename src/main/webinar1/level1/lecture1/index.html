Claude Code: agentic coding environment

Claude Code

1 уровень · 1 лекция
Claude Code — инструмент для AI-native разработки: он работает внутри проекта, помогает разобраться в коде, предложить план, внести изменения и запустить проверки. Разработчик задаёт цель и границы, оценивает результат и отвечает за него.

Не чат в терминале, а помощник в проекте

Обычный AI-чат

Получает переданный текст или фрагмент кода и возвращает совет либо пример. Решение, что переносить в проект, остаётся за человеком.

Claude Code

Может изучать файлы и структуру проекта, искать связанную логику, предлагать план, редактировать файлы и выполнять команды. Ошибка может стать реальным изменением.

Agentic означает, что инструмент не только рассуждает, но и действует: выполняет ограниченные действия внутри рабочей среды — читает файлы, ищет по кодовой базе, правит код и запускает команды.

Claude Code — агент-оболочка, а не сама модель: оболочка даёт терминал, доступ к файлам, цикл работы и правила безопасности, а «думает» подключённая LLM; её можно менять, в том числе через settings.json.

Сквозной пример лекции — Commerce OS, воображаемый интернет-магазин. Его не нужно скачивать или настраивать: проект нужен только для разбора примеров. В частности, на нём рассматривается очередь возвратов, где срочные заявки могут сортироваться неверно.

Вы: «В очереди возвратов срочные заявки иногда оказываются ниже обычных.
Найди связанную логику, но сначала покажи план без изменений.»

Claude: «Нашёл сервис сортировки, связанный контроллер и тест.
Предлагаю сначала проверить правило сортировки, потом показать diff.»

Инструмент ведёт себя как участник рабочего процесса: сначала разбирается в проекте и предлагает конкретный следующий шаг, а не выдаёт абстрактный список возможных причин.

Claude ускоряет инженерную работу, но за результат всё равно отвечаете вы.

Почему важны границы задачи и diff

Даже маленькая правка способна поменять бизнес-правило. Например, исходное условие поднимает наверх только срочные возвраты:

if (refundRequest.isUrgent()) {
    moveToTop(refundRequest);
}

Добавление проверки суммы изменит поведение — наверх попадут и несрочные дорогие возвраты. Возможно, это нужно, но такой результат нельзя считать автоматически разрешённым.

if (refundRequest.isUrgent() || refundRequest.amount() > 100) {
    moveToTop(refundRequest);
}

Diff — список изменений: какие строки добавлены, какие удалены, что поменялось между старой и новой версией файла. Он показывает фактические изменения, поэтому его нужно читать, а не полагаться только на объяснение инструмента.

Именно поэтому расплывчатое поручение вроде «сделай красиво» опасно: инструмент может заодно подчистить структуру, переименовать поля, изменить порядок сортировки или поправить соседние методы «ради консистентности» — и всё это будет выглядеть аккуратно и логично.

Рабочий цикл

  1. Задача и границы: сформулировать, что исправить и что не менять.
  2. Контекст: Claude изучает относящиеся к задаче файлы и тесты.
  3. План или небольшая правка: сначала можно попросить показать план без изменений.
  4. Проверка diff: убедиться, что изменено только ожидаемое.
  5. Проверки: запустить тесты, сборку (build), анализ стиля (lint) и/или ключевой сценарий.
  6. Решение человека: принять изменение, отклонить его или попросить доработать.

Тесты проверяют поведение автоматически; сборка — что проект собирается; lint ищет технические и стилистические проблемы.

В вебинаре этот цикл называют agentic loop: prompt → сбор контекста → действие → проверка → решение человека (принято или доработка). В цикле вы не пассивный наблюдатель: можно добавить контекст, прервать действие (Esc) или направить Claude, если он уходит не туда. Если результата недостаточно, цикл возвращается к сбору контекста; если достаточно — Claude останавливается и ждёт следующий prompt.

Вы: «Исправь порядок отображения возвратов. Сначала покажи план.»

Claude: «Нашёл 3 связанных файла. Предлагаю изменить правило сортировки
и проверить существующий тест на очередь возвратов.»

Вы: «Хорошо. Покажи diff после изменения и что именно проверить.»

Действовать — не значит отвечать за последствия

Claude может искать код, готовить план и черновое изменение, запускать команды и подводить итоги. Человек решает, что менять, ограничивает объём задачи, оценивает diff, интерпретирует проверки и определяет, можно ли принять результат. Помощник способен незаметно расширить задачу «ради улучшения», поэтому изменения должны быть понятными и ограниченными.

Claude ускоряет

  • поиск по проекту;
  • черновой план и черновой код;
  • запуск типовых команд;
  • подготовку сводки по изменениям.

За вами остаётся

  • решение, что вообще менять, и границы задачи;
  • чтение и оценка diff;
  • интерпретация результатов проверок;
  • решение принять, отклонить или доработать правку.

Опаснее всего не полностью ошибочный ответ, а аккуратное изменение «почти по делу», которое слегка выходит за рамки задачи. Сказать «стоп, это вне задачи» или «покажи только план» — по-прежнему работа человека.

Надёжная основа — не заучивание команд, которые могут измениться, а устойчивый принцип: задача → контекст → план → изменение → diff → проверки → решение человека. Если название команды или поверхность изменились, просто сверьтесь с актуальной документацией — сам подход не рассыпается.

Подготовка среды: Git и Node.js

Git помогает видеть изменения, проверять diff и возвращаться к предыдущему состоянию. Node.js нужен для одного из способов установить Claude Code через npm/npx и пригодится в дальнейшей фронтенд-разработке. Устанавливайте актуальную LTS-версию Node.js; команды могут меняться — сверяйтесь с официальной документацией.

macOS

brew install git
brew install node

Если Homebrew нет, Git можно установить через Command Line Tools: xcode-select --install.

Linux

sudo apt install git       # Debian / Ubuntu
sudo dnf install git       # Fedora / RHEL
nvm install --lts          # Node.js через nvm

Windows

winget install --id Git.Git
winget install --id OpenJS.NodeJS.LTS

Проверка установки

git --version
node --version
npm --version

Откройте новое окно терминала после установки, чтобы обновился PATH. Если команда не найдена, сначала перезапустите терминал.

Практика (15–25 минут)

Цель: Почувствовать agentic loop и научиться принимать результат по diff, а не по описанию.

Что сделать

  1. Создайте учебную папку claude-practice/agent-loop, выполните git init, создайте header.txt с двумя строками: Refund requset и Do not touch this line, затем сделайте первый коммит.
  2. Запустите Claude из папки и попросите: «Исправь только Refund requset на Refund request. Ничего больше не меняй. Сначала покажи план, потом diff».
  3. Проверьте план, разрешите правку и посмотрите git diff. Убедитесь, что изменилась только одна строка.
  4. В копии папки попросите «сделай файл аккуратнее» и сравните diff. Не принимайте изменения: отметьте, что было бы helpful overreach.

Проверка

  • В первом diff изменилась только строка с опечаткой.
  • Вы можете объяснить, где в цикле был сбор контекста, действие, проверка и решение человека.
  • Вы назвали хотя бы один пример «заодно», который не входил в задачу.
Главный вывод: используйте Claude Code как действующего технического помощника — чётко ставьте задачу, контролируйте изменения и проверяйте результат.
