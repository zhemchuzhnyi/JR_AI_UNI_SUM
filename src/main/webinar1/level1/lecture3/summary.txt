САММАРИ ЛЕКЦИИ 3
Установка, авторизация, обновления и диагностика — Claude Code, 1 уровень

1. Установка — ещё не готовая среда
Готовность означает, что система находит команду claude, сессия запускается из нужного проекта и shell, диагностика не показывает критических проблем, а авторизация выполнена нужным аккаунтом.

Выбирайте способ установки, который уже подходит вашей машине: пакетный менеджер ОС, npm (если Node.js установлен) или официальный установщик. Официальный скрипт установки — рекомендуемый способ: он ставит готовый бинарь и не требует заранее установленного Node.js. Для npm-установки нужен Node.js 22 или новее. Не устанавливайте новый пакетный менеджер ради одного инструмента. В Windows есть варианты через winget (`winget install Anthropic.ClaudeCode`), PowerShell, CMD и WSL; на нативном Windows полезен Git for Windows — с ним Claude Code выполняет команды через Bash, а без него через PowerShell. Команды и версии могут меняться — актуальные инструкции ищите в официальной документации.

Примеры команд:
macOS:
  brew install --cask claude-code
  npm install -g @anthropic-ai/claude-code
  curl -fsSL https://claude.ai/install.sh | bash

Linux / WSL:
  npm install -g @anthropic-ai/claude-code
  curl -fsSL https://claude.ai/install.sh | bash

Windows PowerShell:
  irm https://claude.ai/install.ps1 | iex
  npm install -g @anthropic-ai/claude-code

Windows CMD:
  curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd

После установки откройте новое окно терминала и проверьте:
  claude --version

Если появляется command not found (в Windows — «'claude' не является внутренней или внешней командой»), чаще всего текущий shell не видит CLI через PATH, терминал не перезапущен или команда запущена в другой среде. Официальный скрипт кладёт бинарь в ~/.local/bin или аналог в домашнем каталоге, глобальный npm-пакет — туда, куда настроен npm prefix. Если prefix указывает на системные каталоги (/usr/local/lib/node_modules), понадобится sudo — это плохой признак: перенастройте prefix на домашний каталог. Свой пользовательский PATH меняется без прав администратора; консоль от имени администратора нужна только для системного PATH всех пользователей. Если не хотите править PATH вручную, можно попросить LLM-чат сгенерировать точную команду под ваш shell. На Apple Silicon используйте совместимые нативные ARM-сборки Homebrew и Node.js. В Docker, dev container и CI CLI должен быть установлен внутри рабочей среды, где находятся файлы и выполняются команды.

2. Запускайте CLI там, где живёт проект
Запускайте Claude Code в той же среде, где лежат проект, Git и инструменты проекта. Для Windows-native проекта обычно подойдёт PowerShell; для проекта в WSL — WSL; для удалённого проекта — SSH-сессия; для контейнерного — сам контейнер или среда, в которой реально доступны файлы и команды.

Проверьте каталог проекта (например, в нём есть README, build.gradle или package.json), затем выполните:
  cd ~/projects/commerce-os
  claude --version
  claude

PowerShell, WSL, Git Bash и терминал IDE могут иметь разные PATH и файловые системы. Установка в одной среде не гарантирует доступ из другой. Локальная установка также не переносится автоматически на SSH-хост или в контейнер.

Пример рассогласования: проект лежит в WSL, а Claude Code запущен из обычного PowerShell. PowerShell не видит linux-путь проекта напрямую, а его PATH, Git и инструменты — другие; в лучшем случае проект будет виден через монтирование WSL, но команды выполнятся уже в Windows-среде. Для проекта в WSL открывайте терминал WSL (или IDE, подключённую к WSL) и запускайте CLI там.

3. Проверка первого запуска
Цепочка первого запуска: открыть терминал в нужной среде → перейти в каталог проекта → claude --version → claude → /doctor → /status. Если всё в порядке — сохраните лог первого запуска; если нет — исправьте shell/PATH/авторизацию/каталог и повторите.

Команды вида /doctor, /status, /compact, /clear выполняются внутри интерактивной сессии Claude Code, а не в обычном shell. В этой лекции подробно разбираются /doctor и /status:
  /doctor
  /status

`claude doctor` — та же диагностика, но запускается из обычного терминала, вне сессии.

• claude --version — видит ли shell CLI и какая версия запускается.
• /doctor — состояние установки, shell, авторизации и окружения.
• /status — состояние сессии, проекта и авторизации.

Предупреждение в /doctor — сигнал проверить среду, а не повод автоматически переустанавливать всё. Если команды отличаются в вашей версии, используйте /help и актуальную справку.

4. Авторизация и обновления
Путь входа может отличаться в зависимости от личной подписки, рабочего/командного аккаунта и корпоративных настроек. Важно убедиться через /status, что CLI авторизован правильной учётной записью. Если аккаунт неверный, завершите сеанс и выполните вход заново по актуальным инструкциям.

Обновляйте тем же способом, которым устанавливали: пакетным менеджером, npm или соответствующим установщиком. Не смешивайте каналы — на машине могут появиться несколько версий, и shell запустит не ту. После обновления проверьте claude --version, откройте сессию и запустите /doctor. Повторный вход после обновления возможен. Не гонитесь за номером версии из чужого видео: чуть новее или старее — не проблема, цель — рабочая и предсказуемая среда.

5. Диагностика частых проблем
• Команда не найдена — проверьте PATH, перезапустите терминал и сравните среду установки и запуска.
• Работает лишь в одном терминале — сравните shell и PATH обычного терминала и IDE.
• Claude не видит проект — проверьте каталог и среду, из которой запущена сессия.
• /doctor показывает неожиданный shell — сопоставьте реальную рабочую среду и текущее окно терминала.
• Не та авторизация или вход зацикливается — сверьте аккаунт в /status, проверьте активный браузерный сеанс и повторите вход.
• Не работает на SSH/в контейнере — проверьте, установлен и запущен ли CLI именно в среде проекта.

PATH — список каталогов, в которых shell ищет команды. При неполадке выясните последовательно: видна ли команда, та ли выбрана среда, тот ли открыт проект, верный ли аккаунт и что сообщает /doctor. Не переустанавливайте всё вслепую.

6. Лог первого запуска
Сохраните короткую запись: дата, проект и каталог, ОС и shell, версию Claude CLI, результат авторизации и /doctor, состояние /status, заметки о том, из какого терминала запускать. Этот лог поможет сравнить рабочее состояние с тем, что изменилось после обновления или смены среды.

7. Доступ курса через JavaRush Gateway
На курсе используется доступ через Gateway JavaRush; личная подписка не требуется. CLI отправляет запросы на Gateway с индивидуальным токеном, а сервер маршрутизирует запросы и учитывает расход.

Два файла настроек:
• ~/.claude/settings.json — глобальный файл в домашней папке: адрес Gateway и личный ключ, работают во всех проектах.
• .claude/settings.local.json — локальные оверрайды для конкретного проекта, эксперименты и личные настройки. Проектный local-файл имеет приоритет над глобальным; обычно он находится в .gitignore.

Ключ — секрет: не показывайте его, не публикуйте settings.json и не коммитьте секреты в Git. Не помещайте ключи в проект.

Пример глобальной конфигурации (вместо заглушки вставляется только выданный вам ключ):

  {
    "env": {
      "ANTHROPIC_BASE_URL": "https://llm.javarush.com",
      "ANTHROPIC_AUTH_TOKEN": "ВАШ_ИНДИВИДУАЛЬНЫЙ_КЛЮЧ",
      "ANTHROPIC_MODEL": "claude-course-fast[1m]",
      "ANTHROPIC_DEFAULT_HAIKU_MODEL": "claude-course-fast",
      "ANTHROPIC_DEFAULT_SONNET_MODEL": "claude-course-fast[1m]",
      "ANTHROPIC_DEFAULT_OPUS_MODEL": "claude-course-pro[1m]",
      "ANTHROPIC_DEFAULT_FABLE_MODEL": "claude-course-max[1m]",
      "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
      "CLAUDE_CODE_AUTO_MODE_SERVER": "0"
    }
  }

Если в settings.json уже есть другие записи, можно заменить их целиком или добавить блок "env" внутрь существующего объекта. Важно сохранить JSON-синтаксис: ключи в кавычках, блоки разделены запятыми.

ANTHROPIC_BASE_URL задаёт адрес Gateway, ANTHROPIC_AUTH_TOKEN — ваш ключ, а CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY включает обнаружение Gateway-моделей. Откройте сессию командой claude и подтвердите доступ через /status.

`ANTHROPIC_MODEL` задаёт модель при каждом запуске и перекрывает выбор в `/model`. Если хочется, чтобы выбор в `/model` запоминался, есть `ANTHROPIC_DEFAULT_MODEL`: она задаёт стартовую модель, но при заданной `ANTHROPIC_MODEL` не срабатывает.

Итог: готовность — это не только установленный CLI, а совпадение среды, проекта и shell, успешная проверка версии и диагностики, правильный аккаунт и безопасное хранение курсового токена.

## Практика (15–25 минут)

**Цель:** Собрать лог первого запуска и проверить, что CLI виден в нужной среде.

**Что сделать:**
1. Откройте терминал в проекте и выполните `claude --version`, затем `claude doctor`.
2. Запустите сессию `claude` и выполните `/doctor` и `/status`.
3. Проверьте `which claude` (macOS/Linux) или `where claude` (Windows) и сравните shell обычного терминала и терминала IDE.
4. Создайте `first-run-log.md`: дата, ОС и shell, путь проекта, версия CLI, статус авторизации, краткий итог `/doctor` и заметки. Не копируйте токен.

**Проверка:**
- Вы понимаете, что показывает каждый из уровней диагностики.
- В логе нет токенов, ключей и других секретов.
- Вы можете объяснить, что делать при `command not found`.

> Если CLI ещё не установлен, выполните текстовую часть: составьте такой же чек-лист и отметьте, какие команды нужно будет запустить.
