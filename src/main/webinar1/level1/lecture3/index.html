Установка, авторизация, обновления и диагностика

Claude Code

1 уровень · 3 лекция
Установить CLI недостаточно: готовая среда — это когда система находит claude, сессия запускается в нужном проекте и shell, диагностика спокойная, а авторизация выполнена нужным аккаунтом.

Установка: выберите подходящий способ

Используйте пакетный менеджер, который уже есть на машине, npm при наличии Node.js 22 или новее либо официальный установщик. Официальный скрипт установки — рекомендуемый способ: он ставит готовый бинарь и не требует заранее установленного Node.js. Не устанавливайте новый пакетный менеджер только ради Claude Code. Точные команды меняются — проверяйте актуальную официальную документацию. После установки откройте новое окно терминала.

macOS

brew install --cask claude-code
# или при наличии Node.js:
npm install -g @anthropic-ai/claude-code
# официальный установщик:
curl -fsSL https://claude.ai/install.sh | bash

Linux / WSL

npm install -g @anthropic-ai/claude-code
# или:
curl -fsSL https://claude.ai/install.sh | bash

Не устанавливайте глобальные npm-пакеты от root, если npm настроен на системный каталог. Предпочтительнее настроить npm prefix в домашний каталог.

Windows PowerShell

winget install Anthropic.ClaudeCode
# или:
irm https://claude.ai/install.ps1 | iex
# или через CMD:
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
# или при наличии Node.js:
npm install -g @anthropic-ai/claude-code

Нативная установка также работает в Git Bash. На нативном Windows полезен Git for Windows: с ним Claude Code выполняет команды через Bash, а без него — через PowerShell; внутри WSL он не нужен.

Проверка команды

claude --version

Команда не найдена — проверьте PATH, перезапустите терминал и убедитесь, что запускаете CLI в той же среде, где ставили его. В Windows то же самое выглядит как «'claude' не является внутренней или внешней командой».

На Apple Silicon используйте нативные версии Homebrew и Node.js (arm64), чтобы не смешивать архитектуры Rosetta и ARM. В Docker, dev container и CI устанавливайте CLI внутри среды, где находятся файлы проекта и выполняются команды.

Запускайте Claude Code там, где находятся проект, Git и инструменты сборки.

Среда запуска важнее, чем кажется

На Windows PowerShell, WSL и Git Bash могут быть разными средами с разными PATH и файловыми системами. Установка в одной и запуск из другой может сделать CLI или проект невидимыми друг для друга. Для проекта в WSL запускайте Claude из WSL; для Windows-native проекта — из PowerShell или настроенного Git Bash.

Пример: проект лежит в WSL, а Claude Code запущен из обычного PowerShell. PowerShell не видит linux-путь проекта напрямую, а его PATH, Git и инструменты — другие; в лучшем случае проект будет виден через монтирование WSL, но команды выполнятся уже в Windows-среде. Для проекта в WSL открывайте терминал WSL (или IDE, подключённую к WSL) и запускайте CLI там.

То же правило относится к SSH и контейнерам: локальная установка на ноутбуке не делает CLI доступным на удалённой машине. Установите и запускайте его там, где лежат файлы и выполняются команды проекта. Перед запуском перейдите в корень проекта — например, туда, где находятся README, build.gradle или package.json.

Первый запуск и диагностика

cd ~/projects/commerce-os
claude --version
claude

# уже внутри интерактивной сессии:
/doctor
/status

Цепочка такая: терминал в нужной среде → cd в каталог проекта → claude --version → claude → /doctor → /status. Если всё спокойно — сохраните лог первого запуска; если нет — исправьте shell, PATH, авторизацию или каталог и повторите.

  • claude --version проверяет, видит ли shell команду и какая версия запускается.
  • claude открывает сессию из текущей папки проекта.
  • /doctor проверяет установку, shell, авторизацию и окружение; предупреждение — повод проверить контекст, а не сразу переустанавливать всё.
  • /status показывает, активна ли сессия, виден ли проект и в порядке ли авторизация: спокойный /status вместе с работающими --version и /doctor означает хороший старт.

Команды вида /... вводятся внутри сессии, не в обычном shell. Отдельно есть claude doctor — отчёт диагностики из обычного терминала, вне сессии; /doctor — та же проверка внутри сессии. Если названия или формат вывода отличаются, ориентируйтесь на встроенную /help, текущую версию и актуальную справку.

Авторизация и обновления

Способ входа зависит от подписки, рабочего или командного аккаунта и корпоративных настроек. Важно не то, как выглядит окно входа, а то, что CLI авторизован нужной учётной записью. Проверяйте результат через /status; при неверном аккаунте завершите текущий сеанс и выполните вход заново по актуальным инструкциям.

Обновляйте CLI тем же способом, которым устанавливали: Homebrew через Homebrew, npm через npm, установщик — через соответствующий канал. Смешивание способов может оставить несколько версий, и shell может запускать не ту. После обновления проверьте claude --version, откройте сессию и запустите /doctor. Повторная авторизация после обновления возможна. И не гонитесь за номером версии из чужого видео: чуть новее или старее — не проблема, цель — рабочая и предсказуемая среда.

Быстрый разбор неполадок

«command not found»

Shell не находит команду: проверьте PATH, способ установки, перезапустите терминал и сверьте текущую среду.

Работает только в одном терминале

Сравните shell и профиль среды в обычном терминале и IDE: они могут использовать разные PATH.

Claude не видит проект

Проверьте текущий каталог и откуда запущена сессия. CLI мог стартовать не из корня проекта или из другой файловой среды.

Не та авторизация

Проверьте аккаунт через /status, выйдите из неверного сеанса и пройдите вход заново.

/doctor показывает неожиданный shell

Терминал, из которого выполнен вход, не совпадает с той средой, где лежит проект. Сопоставьте реальную рабочую среду и текущее окно терминала.

Локально работает, а по SSH или в контейнере — нет

CLI установлен на одной машине, а проект живёт и запускается на другой. Проверьте, где именно должны исполняться команды проекта.

PATH — список каталогов, в которых shell ищет команды. Если файл CLI установлен, но его каталог не входит в PATH текущей сессии, команда не будет найдена. Свой пользовательский PATH меняется без прав администратора; консоль от администратора нужна только для системного PATH всех пользователей. Проверяйте симптомы и среду по очереди вместо того, чтобы переустанавливать всё наугад.

Правило диагностики: видна ли команда? Запущена ли она в среде проекта? Верный ли аккаунт? Что сообщает /doctor?

Лог первого запуска

Сохраните короткую запись о рабочей среде — это точка сравнения при неполадках после обновлений:

Лог первого запуска Claude Code
Дата: 2026-05-24
Проект и каталог: ~/projects/commerce-os
ОС и shell: macOS / zsh (или Windows / PowerShell, WSL и т. п.)
Версия Claude CLI: 2.1.x
Авторизация: проверена через /status
/doctor: результат диагностики
/status: сессия активна, проект открыт
Заметки: из какого терминала запускаю Claude

Запись помогает быстро увидеть, что изменилось: shell, версия, путь проекта или авторизация.

Доступ курса через JavaRush Gateway

Для курса доступ предоставляется через серверный Gateway JavaRush; личная подписка не нужна. CLI направляет запросы на шлюз с индивидуальным токеном, а шлюз маршрутизирует запросы и учитывает расход.

Глобально: ~/.claude/settings.json

Хранит адрес Gateway и индивидуальный ключ. Настройка действует во всех проектах. Файл и ключ нельзя коммитить в Git или публиковать.

Локально в проекте: .claude/settings.local.json

Личные настройки и эксперименты для одного проекта. Не коммитится; обычно добавлен в .gitignore. Его значения имеют приоритет над глобальными.

Пример глобальных настроек: вставляйте только выданный вам индивидуальный ключ. Не публикуйте этот файл и не помещайте секреты в проект.

{
  "env": {
    "ANTHROPIC_BASE_URL": "https://llm.javarush.com",
    "ANTHROPIC_AUTH_TOKEN": "ВАШ_ИНДИВИДУАЛЬНЫЙ_КЛЮЧ",
    "ANTHROPIC_MODEL": "claude-course-fast[1m]",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "claude-course-fast",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "claude-course-fast[1m]",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "claude-course-pro[1m]",
    "ANTHROPIC_DEFAULT_FABLE_MODEL": "claude-course-max[1m]",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_MODE_SERVER": "0"
  }
}

Если в settings.json уже есть другие записи, не заменяйте файл целиком: сохраните резервную копию, добавьте или обновите только блок "env" и не удаляйте незнакомые ключи вроде model, permissions и hooks. Важно сохранить JSON-синтаксис: ключи в кавычках, блоки разделены запятыми.

  • ANTHROPIC_BASE_URL — адрес Gateway, куда CLI отправляет запросы.
  • ANTHROPIC_AUTH_TOKEN — личный ключ доступа и учёта расхода.
  • CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY — включает обнаружение моделей Gateway в CLI.

ANTHROPIC_MODEL задаёт модель при каждом запуске и имеет приоритет над сохранённым выбором /model. /model переключает модель в текущей сессии, но следующий запуск снова возьмёт ANTHROPIC_MODEL. ANTHROPIC_DEFAULT_MODEL задаёт стартовую модель, если ANTHROPIC_MODEL не задана.

Для проверки откройте сессию командой claude и посмотрите /status. Если состояние выглядит нормальным, технический старт собран: базовая среда (Git, Node.js), сам Claude Code, остальной стек проекта и рабочий доступ через Gateway.

Практика (15–25 минут)

Цель: Собрать лог первого запуска и проверить, что CLI виден в нужной среде.

Что сделать

  1. Откройте терминал в проекте и выполните claude --version, затем claude doctor.
  2. Запустите сессию claude и выполните /doctor и /status.
  3. Проверьте which claude (macOS/Linux) или where claude (Windows) и сравните shell обычного терминала и терминала IDE.
  4. Создайте first-run-log.md: дата, ОС и shell, путь проекта, версия CLI, статус авторизации, краткий итог /doctor и заметки. Не копируйте токен.

Если Claude Code недоступен: выполните доступную часть шагов вручную в редакторе и терминале; недоступные команды разберите по официальной документации. Критерии проверки те же.

Проверка

  • Вы понимаете, что показывает каждый из уровней диагностики.
  • В логе нет токенов, ключей и других секретов.
  • Вы можете объяснить, что делать при command not found.

Если CLI ещё не установлен, выполните текстовую часть: составьте такой же чек-лист и отметьте, какие команды нужно будет запустить.

Главное: успешная установка — это не просто файл CLI, а согласованная среда запуска, нужный проект и shell, проверенные версия и сессия, корректная авторизация и безопасно хранимый токен.
