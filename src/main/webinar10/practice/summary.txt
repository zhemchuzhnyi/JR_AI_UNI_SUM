# Практика вебинара 10 — три хука на три группы

Это отдельное capstone-задание вебинара 10, а не замена практикам в конце лекций. Вы собираете обвязку игрушечного репозитория: три хука — по одному на каждую группу событий — и показываете, что автоматика живёт, приносит пользу и умеет выключаться.

Цель — прожить hooks с трёх сторон:

- **после действия** — сигнал, когда Claude закончил;
- **до действия** — предохранитель на `rm`;
- **жизнь сессии** — журнал промптов в репозитории.

Плюс инженерная дисциплина: лестница раскатки, демо-прогоны, дебаг молчащего хука и путь назад.

## Что получится

- `.claude/settings.json` с тремя хуками — в git;
- скрипты-обработчики в `.claude/hooks/`;
- журнал сессии `.claude/session-log.md` — в репозитории;
- `log/` с четырьмя демо-прогонами;
- README: какой хук на какое событие, что делает и зачем, почему журнал в репо, как раскатывали, как чинили;
- блок «как выключить»: убрать блок, `disableAllHooks`, откат на ступень ниже.

## Безопасность и рамки

Работайте только в игрушечном репозитории с фейковыми файлами:

- `notes-old.md`, `draft.md`, `src/report.ts` — учебные файлы, которые не жалко;
- `rm` не выполняется: guard только читает JSON и проверяет строку команды;
- журнал не пишет env-переменные, токены, куски `.env` и реальные персональные данные;
- звуковой сигнал на macOS — `say`; на Windows/Linux честный fallback — запись в лог;
- не подключайте production-репозиторий, реальные базы и чужие сервисы.

Если Claude Code недоступен, все проверки можно выполнить вручную: подать скриптам тестовый JSON и записать результаты. Важно не имитировать успех молча — в `log/` явно пометьте, что прогон симулирован.

## Шаг 1. Игрушечный репозиторий

Создайте отдельную папку и минимальный проект:

```bash
mkdir -p hook-lab/.claude/hooks hook-lab/log hook-lab/src
cd hook-lab
git init
printf '# Hook lab\n' > README.md
printf 'draft\n' > notes-old.md
printf 'export const report = true;\n' > src/report.ts
git add . && git commit -m "baseline"
```

Зафиксируйте baseline, чтобы потом было видно, какие изменения внесла автоматика. Никаких секретов и реальных данных.

## Шаг 2. Три хука

### 2.1. Stop — сигнал завершения

Событие `Stop` срабатывает, когда Claude закончил отвечать. На macOS можно сказать вслух, на другой системе — дописать строку в лог.

```bash
#!/usr/bin/env bash
# .claude/hooks/stop-signal.sh
if command -v say >/dev/null 2>&1; then
  say "Claude finished" >/dev/null 2>&1 || true
else
  echo "$(date -u +%FT%TZ) Claude finished" >> log/stop.log
fi
exit 0
```

Регистрация в `.claude/settings.json`:

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          { "type": "command", "command": "\"${CLAUDE_PROJECT_DIR}\"/.claude/hooks/stop-signal.sh" }
        ]
      }
    ]
  }
}
```

Зачем это в жизни: длинная задача работает, вы занимаетесь своими делами и возвращаетесь к терминалу по сигналу, а не по интуиции.

### 2.2. PreToolUse — предохранитель на rm

Отдельного инструмента «удалить файл» нет: удаление — это Bash-команда `rm`. Поэтому before-hook ловит `Bash` и проверяет строку команды.

```bash
#!/usr/bin/env bash
# .claude/hooks/block-rm.sh
INPUT=$(cat)
COMMAND=$(printf '%s' "$INPUT" | jq -r '.tool_input.command // empty')

if printf '%s' "$COMMAND" | grep -qw "rm"; then
  echo "Blocked: удаление файлов — только руками" >&2
  exit 2
fi

exit 0
```

Регистрация:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "if": "Bash(rm *)",
        "hooks": [
          { "type": "command", "command": "\"${CLAUDE_PROJECT_DIR}\"/.claude/hooks/block-rm.sh" }
        ]
      }
    ]
  }
}
```

Проверка без выполнения `rm`:

```bash
chmod +x .claude/hooks/block-rm.sh
echo '{"tool_name":"Bash","tool_input":{"command":"rm notes-old.md"}}' | .claude/hooks/block-rm.sh
echo $?   # ожидаем 2
```

Скрипт только читает JSON и проверяет строку. Он не должен запускать `eval`, `bash -c` или саму команду из поля `command`.

Честная рамка: это guardrail от буквального `rm`, а не гарантия. Удалить файл можно и другими способами, а жёсткий запрет — это deny-правило в permissions.

### 2.3. UserPromptSubmit — журнал в репозитории

Событие `UserPromptSubmit` срабатывает на каждый ваш промпт. Журнал живёт в репозитории, потому что transcript в `~/.claude` не коммитится и остаётся только на вашей машине.

```bash
#!/usr/bin/env bash
# .claude/hooks/session-log.sh
INPUT=$(cat)
PROMPT=$(printf '%s' "$INPUT" | jq -r '.prompt // empty')
[ -z "$PROMPT" ] && exit 0

{
  printf '\n## %s\n' "$(date -u +%FT%TZ)"
  printf '%s\n' "$PROMPT"
} >> "${CLAUDE_PROJECT_DIR}/.claude/session-log.md"

exit 0
```

Регистрация:

```json
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [
          { "type": "command", "command": "\"${CLAUDE_PROJECT_DIR}\"/.claude/hooks/session-log.sh" }
        ]
      }
    ]
  }
}
```

Правила журнала:

- не писать env-переменные, токены и содержимое `.env`;
- не писать реальные персональные данные;
- не превращать журнал в свалку: промпт и дата — достаточно;
- если нужен ответ Claude, его можно взять из `Stop` (`last_assistant_message`), но в журнал кладите короткий фрагмент.

## Шаг 3. Лестница раскатки для rm-guard

Не включайте blocking сразу. Проживите три ступени и зафиксируйте их в `log/rollout.md`:

1. **Log-only.** Скрипт печатает команду-кандидат в stderr и возвращает `exit 0`. Проверьте, что matcher не ловит лишние Bash-команды.
2. **Non-blocking.** Скрипт печатает предупреждение, но всё ещё возвращает `exit 0`. Убедитесь, что сигнал полезен и не шумит.
3. **Narrow blocking.** Скрипт возвращает `exit 2` только для `rm`. Проверьте на фейковом JSON.

Для format-on-edit или журнала blocking вообще не нужен: они остаются на non-blocking ступени. Не превращайте лестницу в обязательный ритуал там, где хук не умеет мешать.

## Шаг 4. Четыре демо-прогона

Соберите доказательства, что автоматика жила. Не «настройки выглядят правильно», а логи:

1. **after:** Claude закончил задачу — сработал `Stop`-сигнал, в `log/stop.log` или в выводе есть отметка.
2. **before:** попытка `rm` — хук заблокировал, в логе есть причина блока и `exit 2`.
3. **session:** журнал наполнился за рабочую сессию — промпты и даты на месте.
4. **debugging:** один хук молчал — в README разбор по пяти вопросам: загружен, событие, matcher, скрипт, side effects.

Для четвёртого прогона можно специально сломать matcher (`edit` вместо `Edit`) или JSON, затем найти причину через `/hooks`, `Ctrl+O`, `/debug` или ручной запуск. После фикса — снова демо.

## Шаг 5. README и путь назад

В README проекта должны быть:

### Карта хуков

| Группа | Событие | Скрипт | Что делает | Зачем |
|---|---|---|---|---|
| после | `Stop` | `stop-signal.sh` | звук или запись в лог | вернуться к терминалу |
| до | `PreToolUse` + `Bash` | `block-rm.sh` | `exit 2` на `rm` | защита от необратимого |
| сессия | `UserPromptSubmit` | `session-log.sh` | журнал промптов | память и отчётность |

### Лестница и дебаг

- как `block-rm.sh` прошёл log-only → non-blocking → narrow blocking;
- какие лишние срабатывания поймали и как сузили matcher;
- пять вопросов, по которым нашли молчащий хук;
- что изменили после фикса.

### Как выключить

- убрать блок из `.claude/settings.json` — настройки перечитываются на лету;
- `"disableAllHooks": true`;
- `claude --settings '{"disableAllHooks": true}'`;
- откатить хук на ступень ниже и записать причину рядом с ним.

## Проверка

- `.claude/settings.json` с тремя хуками лежит в git.
- Три хука соответствуют трём группам событий: `Stop`, `PreToolUse`, `UserPromptSubmit`.
- `block-rm.sh` возвращает `2` на фейковом JSON и объясняет причину в stderr.
- Скрипт не выполняет команду из JSON и не содержит реальных опасных действий.
- `rm`-guard раскатан по лестнице, а не включён сразу blocking.
- Журнал `.claude/session-log.md` лежит в репозитории и не содержит секретов.
- В `log/` есть четыре демо-прогона, включая разбор молчащего хука.
- README объясняет, какие события покрыты, что автоматика делает, почему ей можно доверять и как её выключить.
- Нет реальных секретов, production-данных и опасных команд.
- Если Claude Code недоступен, прогоны выполнены вручную и честно помечены как симуляция.

## Если Claude Code недоступен

Можно проверить скрипты без запуска Claude Code:

```bash
printf '%s' '{"prompt":"проверь сортировку"}' | .claude/hooks/session-log.sh
printf '%s' '{"tool_name":"Bash","tool_input":{"command":"rm notes-old.md"}}' | .claude/hooks/block-rm.sh
echo $?
```

Запишите в `log/` команды, JSON и коды возврата. В README укажите, что реальная сессия Claude Code не запускалась, а hook-контракты проверены вручную. Конфиг, журнал, лестница и разбор дебага всё равно обязательны.
