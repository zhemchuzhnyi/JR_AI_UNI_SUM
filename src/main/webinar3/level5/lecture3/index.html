Context budget, /context и compaction

Claude Code

5 уровень · лекция 3
Даже чистый контекст со временем распухает. Гигиена сессии — это не «Claude стал хуже», а управление рабочим пространством: посмотреть `/context`, при необходимости сделать `/compact`, а для новой задачи пересобрать сессию.

Даже чистый контекст распухает

Отобрать правильные файлы — половина дела. Дальше набор живёт сам: диалог растёт, копятся выводы команд, отвергнутые гипотезы не исчезают. Через полчаса вы работаете уже не с утренним аккуратным набором, а с его раздутой версией.

Context budget — у окна есть предел, за него конкурируют история диалога, файлы, вывод команд и правила проекта. Длинный лог легко стоит дороже пяти строк с goal, scope и ограничениями. Половину бюджета съел шум — рассуждение поплыло.

Пример: в Commerce OS после неверного пароля пустой экран. Старт чистый — LoginController.java, SessionService.java, AuthFlowTest.java, короткий лог. Через полчаса — три гипотезы, длинный вывод тестов, SSO, отвергнутое решение. Формально всё по теме, практически окно захламлено.

Чтение вывода /context

/context показывает, чем занято окно. Точный формат зависит от версии — сверяйтесь с /help. Это приборная панель: шум не уберёт, но покажет индикатор.

/context
История диалога: большая
Файлы в работе: LoginController.java, SessionService.java, AuthFlowTest.java
Вывод команд: auth-error.log, test output
Проектные инструкции: CLAUDE.md
Доп. сигналы: memory, rules

В более подробном выводе видны вклад каждого слоя и свободное место:

/context

  System prompt     3.2k   ( 2%)   служебные инструкции
  System tools     12.1k   ( 6%)   описания встроенных инструментов
  MCP tools        21.4k   (11%)   подключённые внешние серверы
  Memory files      1.8k   ( 1%)   CLAUDE.md, rules, auto memory
  Messages         45.2k   (22%)   ваш диалог, файлы, логи
  Free space      116.3k   (58%)

Цифры условные: размер окна зависит от модели, формат — от версии. Смысл в том, что служебный минимум (system prompt и встроенные инструменты) есть всегда, каждый MCP-сервер занимает место, разросшийся CLAUDE.md оплачивается заново в каждой сессии, а по ходу работы растёт в первую очередь Messages.

Читайте как ответ на три вопроса:

  • не съела ли история слишком много места;
  • не лежат ли выводы команд, которыми уже никто не пользуется;
  • остались ли в фокусе файлы и ограничения, ради которых сессия начиналась.

Файлы на месте, но история огромная, а лог тянет на себя непропорционально много — сигнал в пользу /compact. Рядом болтаются SSO, UX формы и README соседнего модуля — нужна радикальная уборка.

Не можете в одном абзаце ответить «цель, scope, что мешает» — проблема не в объёме: сессия размывает задачу.

/compact: сжатие без иллюзий

/compact — компромисс: подробная история меняется на сжатую сводку. Места больше, часть деталей теряется. Это не «сохранить всё», а «оставить главное».

Аналогия — протокол встречи: цель, решения, открытые вопросы. Содержательная сессия даст хорошую сводку; хаотичная — просто сожмёт хаос.

Делайте compaction не молча, а с указанием, что сохранить:

/compact Сохрани:
- цель: исправить пустой экран после неверного пароля
- область изменений: только src/auth/* и AuthFlowTest
- ограничения: не менять public API, не трогать миграции
- отклонённая гипотеза: проблема не в SessionService
- приёмка: показать ошибку пользователю и сохранить текущее поведение успешного логина

Логи, ложные гипотезы и второстепенное отпускаете; цель, scope, ограничения и проверенные выводы уносите в сводку.

Помогает, если task spec лежит в файле:

Цель: исправить пустой экран после неверного пароля
Область изменений: src/auth/*, AuthFlowTest.java
Ограничения:
- не менять public API
- не добавлять зависимости
Приёмка:
- пользователь видит ошибку
- успешный логин работает как раньше

После compaction восстановите фокус коротким напоминанием:

Продолжаем ту же задачу.
Повторяю цель: убрать пустой экран после неверного пароля.
Прочитай заново LoginController.java и AuthFlowTest.java.
Сохраняем прежний session API и не выходим за src/auth/*.

После compaction нельзя давить «ты же 20 минут назад говорил». В окне сводка, а не полная история — надёжнее заново поднять факт из файла, теста или task spec.

Сжатие может произойти и без вашей команды: когда окно почти заполнено, Claude Code запускает auto-compact. В строке состояния виден индикатор вида «Context left until auto-compact». Авто-сжатие — тот же /compact, но список того, что сохранить, за вас никто не составит. Поэтому длинную сессию выгоднее сжать вручную на удобной границе. Порог можно сдвинуть командой /autocompact 500k.

После сжатия project-root CLAUDE.md, общие rules и auto memory подгружаются заново. path-scoped rules, привязанные к путям, и вложенные CLAUDE.md вернутся только когда Claude снова прочитает файл из нужной области. До пяти файлов, которые Claude Code недавно менял, он перечитывает сам, остальные остаются строкой в сводке — перед правкой их нужно открыть заново.

Когда compaction уже не помогает

/clear — следующий инструмент гигиены, когда compaction мало.

  • задача та же, история тяжёлая — сначала /compact;
  • заехала другая тема — чище обнулить беседу;
  • не можете за пять-шесть строк пересобрать goal, scope и evidence — новая сессия дешевле спасения старой.

Отдельный количественный ориентир: когда занято около 60% окна, агент может хуже следовать прежним инструкциям, возвращаться к отвергнутым решениям или уходить в сторону от задачи. Это сигнал проверить /context и решить, пора ли выполнять /compact или завершать сессию.

/clear — новый разговор в том же проектном окружении. Fresh session — новый контейнер, куда вы заново приносите рамку: goal, scope, ограничения, evidence. Пока задача одна — сохраняете форму сессии; форма потеряна — пересобираете.

Жизненный цикл сессии в Commerce OS

Старт: task spec, узкий scope, нужные файлы.

Цель: исправить пустой экран после неверного пароля
Область изменений: src/auth/*, AuthFlowTest.java
Ограничения:
- не менять public API
- не трогать миграции
Приёмка:
- ошибка видна пользователю
- успешный логин работает как раньше

Через время: длинный вывод тестов, две ложные гипотезы, обсуждение SSO. Claude отвечает менее точно. Диагностика:

/context

История большая, auth-файлы в фокусе, но вывод команд разросся, а старая гипотеза про SessionService влияет на рассуждение. Это /compact, не /clear: задача та же.

/compact Сохрани:
- цель и критерии приёмки из task spec
- область изменений: только src/auth/*
- отклонённая гипотеза: SessionService не корень проблемы
- следующий шаг: проверить рендер ошибки в LoginController

После сжатия — короткое восстановление рамки:

Продолжаем тот же bugfix.
Повторяю: меняем только src/auth/*, public API не трогаем.
Прочитай заново LoginController.java и AuthFlowTest.java.
Проверь, почему ошибка не попадает в рендер.

Баг локализован — прилетает новая просьба: «Раз уж вы в форме логина, добавьте подсказку про SSO и поменяйте тексты ошибок». Задача сменилась с bugfix на UX — /clear или fresh session с новым мини-спеком. Так diff остаётся управляемым.

Сессия тяжелеет — /context. Задача та же — /compact. Задача сменилась — новый контейнер.

Практика (15–25 минут)

Цель: провести гигиену сессии: прочитать /context, сделать /compact с сохранением рамки и выбрать /clear или fresh session для новой задачи.

Что сделать

  1. Возьмите учебный bugfix: пустой экран после неверного пароля. Используйте только вымышленные данные.
  2. Зафиксируйте в файле цель, область изменений, ограничения и критерии приёмки.
  3. Выполните /context и выпишите, что занимает окно: история, файлы, логи, правила, критерии.
  4. Найдите один источник шума и решите, что с ним делать: убрать, сжать или оставить.
  5. Выполните /compact с явным списком того, что сохранить: цель, scope, ограничения, отклонённые гипотезы, следующий шаг.
  6. После сжатия отправьте короткое напоминание и попросите Claude пересказать цель, границы и следующий шаг.
  7. Представьте новую несвязанную просьбу про SSO-подсказку. Решите, нужен ли /clear или fresh session, и соберите для неё новый мини-спек.

Проверка

  • Вы можете объяснить, что занимает контекст и что является шумом.
  • После /compact сохранились цель, scope, ограничения и критерии приёмки.
  • Claude после сжатия правильно пересказывает рамку.
  • Для новой задачи выбран /clear или fresh session, а не продолжение старой.
  • Вы можете назвать, когда достаточно /compact, а когда нужен новый контейнер.
